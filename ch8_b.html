Conceptual model

Let us consider a grid cell with NDVI observations through time:

\[ NDVI_1, NDVI_2, NDVI_3, \ldots, NDVI_T. \]

We model current NDVI as a function of its previous three layers:

\[ NDVI_t = \beta_0 + \beta_1 NDVI_{t-1} + \beta_2 NDVI_{t-2} + \beta_3 NDVI_{t-3} + \epsilon_t. \]

Here:

  • \(\beta_0\) is the intercept.
  • \(\beta_1\) measures the relationship with NDVI one layer earlier.
  • \(\beta_2\) measures the relationship with NDVI two time steps earlier.
  • \(\beta_3\) measures the relationship with NDVI three time steps earlier.
  • \(\epsilon_t\) represents unexplained variation.

This is an autoregressive-style regression because previous NDVI values are used to explain current NDVI. It is implemented separately for every grid cell.

Important

A lag of one means one raster layer, not necessarily one day or one month. Its physical meaning depends on the temporal spacing of the input files.

What this code does

list.files() searches the NDVI directory for files ending in .tif. Setting full.names = T returns complete paths, allowing rast() to locate each file.

sort() places filenames in alphanumeric order. This produces chronological order only if the filenames contain dates in a sortable format, such as NDVI_2020_01.tif, NDVI_2020_02.tif, and so on. Before fitting the model, inspect the filenames and confirm that they are arranged chronologically.

When app() evaluates a cell, it passes a vector like x_example to the function. The vector contains that cell’s values in raster-layer order.

Non-land cells contain only NA values. Some land cells may also contain occasional NA values because of clouds, missing observations, or quality screening.

The first row cannot have a one-step lag, so lag_1 begins with NA. Similarly, lag_2 begins with two missing values and lag_3 begins with three. Consequently, the first three rows cannot be used to fit the regression.

Define the cellwise regression function

NDVI_pred_mod <- function(x) {
  # app() may provide values in a matrix-like form; convert to a vector.
  x <- as.numeric(x)

  tryCatch({
    # Skip cells that contain no NDVI observations, such as non-land pixels.
    if (!all(is.na(x))) {

      # Construct one-, two-, and three-step lagged NDVI predictors.
      x1 <- c(NA, x[-length(x)])
      x2 <- c(NA, x1[-length(x1)])
      x3 <- c(NA, x2[-length(x2)])

      # Column 1 is current NDVI; columns 2-4 are lagged NDVI.
      lagInput <- cbind(x, x1, x2, x3)

      # Fit current NDVI as a function of the previous three layers.
      # lm() excludes rows containing NA values.
      regCoeff <- lm(lagInput[, 1] ~ lagInput[, 2:4])

      # Extract the intercept and three slope coefficients.
      interc <- regCoeff$coefficients[1]
      a1 <- regCoeff$coefficients[2]
      a2 <- regCoeff$coefficients[3]
      a3 <- regCoeff$coefficients[4]

      return(c(interc, a1, a2, a3))

    } else {
      # Return four missing coefficients for a non-land cell.
      return(rep(NA, 4))
    }
  }, error = function(e) {
    # If the model cannot be fitted, preserve the output structure.
    return(rep(NA, 4))
  })
}

Why return exactly four values?

The function returns one value for each model coefficient:

  1. Intercept, \(\beta_0\)
  2. Lag-1 coefficient, \(\beta_1\)
  3. Lag-2 coefficient, \(\beta_2\)
  4. Lag-3 coefficient, \(\beta_3\)

Because every cell must return the same number of values, failed models and non-land cells also return a four-element vector, but all four elements are NA.

Why use tryCatch()?

A cellwise model can fail for reasons such as:

  • too few complete observations;
  • all valid NDVI values being identical;
  • perfect collinearity among lagged predictors;
  • singular or otherwise unusable model fits.

tryCatch() prevents one problematic cell from stopping the global raster operation. It converts a model error into four NA coefficients.

Important

tryCatch() handles errors, but it can also hide their causes. While developing the function, test it on selected cells without tryCatch() so that you can see and interpret any model errors.

Apply the regression to every raster cell

coeffVal <- app(ndviStack, NDVI_pred_mod)

names(coeffVal) <- c(
  "intercept",
  "lag_1_coefficient",
  "lag_2_coefficient",
  "lag_3_coefficient"
)

coeffVal

terra::app() visits each grid cell, gathers its values across all layers, supplies that vector to NDVI_pred_mod(), and writes the four returned coefficients to four output raster layers.

The spatial geometry of the input is retained. Therefore, every cell in the output corresponds to the same location as the input NDVI rasters.

Map and interpret model coefficients

plot(
  coeffVal[["intercept"]],
  main = "Regression intercept",
  range = c(0, 1)
)

plot(
  coeffVal[["lag_1_coefficient"]],
  main = "Lag-1 NDVI coefficient"
)

plot(coeffVal, main = names(coeffVal))

Interpret the coefficient maps carefully:

  • A positive lag coefficient indicates that, after accounting for the other lags, higher NDVI in earlier layers is associated with higher current NDVI.
  • A negative lag coefficient indicates an inverse partial relationship after accounting for the other lags.
  • Larger absolute values indicate a stronger fitted relationship on the scale of the model.
  • The intercept is the predicted current NDVI when all three lagged NDVI values equal zero. That condition may not be ecologically meaningful for every location.

A coefficient map is not a prediction map. It shows how fitted model parameters vary spatially.

Generate next-time-step predictions for a single cell

The fitted equation can be used to predict the next NDVI value from the three most recent observations. If the model returns coefficients (b0, b1, b2, b3), then:

\[ \widehat{NDVI}_{T+1} = b_0 + b_1 NDVI_T + b_2 NDVI_{T-1} + b_3 NDVI_{T-2}. \]

coefs <- NDVI_pred_mod(test_series)

next_ndvi <- coefs[1] +
  coefs[2] * test_series[length(test_series)] +
  coefs[3] * test_series[length(test_series) - 1] +
  coefs[4] * test_series[length(test_series) - 2]

This example is for one time series. To create a full prediction raster, we would apply the same calculation cellwise using the coefficient rasters and the final three NDVI layers.

A multilayer GeoTIFF is written with one layer for each coefficient. The output should be checked after writing to confirm its layer names, coordinate reference system, spatial extent, and missing-value pattern.

Key takeaways

  • A multilayer raster can represent time through its layer dimension.
  • terra::app() allows the same function to be run independently for each grid cell.
  • Lagged variables align earlier observations with current NDVI.
  • Non-land pixels require explicit missing-value handling.
  • tryCatch() makes large cellwise computations resilient, but errors should still be investigated during development.
  • Raster-layer order determines the time order, so file sorting and date verification are essential.
  • Regression coefficients describe fitted relationships; additional validation is required before using the model for forecasting.
