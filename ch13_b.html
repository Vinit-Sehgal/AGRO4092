What we will learn?

We will fit and optimize a physics-based nonlinear response curve with bounded nonlinear least squares (NLS) using minpack.lm::nlsLM(). We will compare that interpretable curve with a Random Forest model that learns the relationship directly from the data. Particle Swarm Optimization (PSO) is introduced later as an optional replacement for the optimizer, not as a second physical model. Finally, we will turn the optimization steps into reusable functions and apply them to spatial soil-moisture (SM) and evaporative-fraction (EF) data.

Let’s follow one clear workflow:

observations → physical equation → parameter bounds → optimization → fitted curve → reusable function → parameter maps

The bigger picture

The SM–EF relationship is our case study. The same R workflow can be adapted to other environmental models when you have an equation, unknown parameters, and observations for fitting.

The physical question

Evaporative fraction (EF) describes the fraction of available surface energy used for evapotranspiration. We will model how EF changes as soil moisture (SM) decreases. These periods when SM decreases continuously for several consecutive observations are called soil-moisture drydowns.

We will represent three soil-moisture regimes: 1. a dry regime, where water strongly limits EF; 2. a transition regime, where EF increases with SM; and 3. a wet regime, where EF reaches a plateau.

We are interested in how evaporative fraction (EF) responds as the soil progressively loses water. Wetting events such as rainfall interrupt this process by suddenly increasing soil moisture and resetting the soil-water conditions. For this reason, we focus on drydown periods.

Why not fit every observation?

If we mix wetting and drying periods together, observations with similar SM may represent very different conditions. One observation may be part of a gradual drydown, while another may occur immediately after rainfall.

By focusing on drydowns, we isolate periods when changing soil-water availability is more directly connected to the evolution of EF.

We will therefore first identify periods of consecutive soil-moisture decline and use these observations for model fitting.

Define the physics-based response curve

We will use the following piecewise-linear model:

\[ EF(SM)= \begin{cases} 0, & SM \leq \theta_d \\ EF_{max}\dfrac{SM-\theta_d}{\theta_w-\theta_d}, & \theta_d < SM < \theta_w \\ EF_{max}, & SM \geq \theta_w. \end{cases} \]

The three parameters are:

  • \(\theta_d\): dry threshold;
  • \(\theta_w\): wet threshold; and
  • \(EF_{max}\): EF at the wet plateau.

Translate the equation into an R function.

piecewise_EF <- function(SM, theta_d, theta_w, EF_max) {
  # Apply the three physical regimes to every SM value.
  ifelse(
    SM <= theta_d,
    0,
    ifelse(
      SM >= theta_w,
      EF_max,
      EF_max * (SM - theta_d) / (theta_w - theta_d)
    )
  )
}

Bounds are part of the model

The dry threshold is searched in the lower part of the observed SM distribution, while the wet threshold is searched in the upper part. This encourages \(\theta_d < \theta_w\) and avoids implausible combinations. If many fitted values reach a bound, inspect the data and reconsider the bound rather than accepting the result automatically.

Fit the physical model with bounded NLS

minpack.lm::nlsLM() uses a Levenberg–Marquardt nonlinear least-squares algorithm. It adjusts the three parameters to minimize squared prediction errors while respecting the bounds. We use it throughout Chapters 13 and 14 so that the physical model is consistent.

Choose starting values halfway between the lower and upper bounds. Starting inside the allowed range gives the optimizer a valid place to begin.

Why use nlsLM()?

nlsLM() keeps the familiar model-formula interface, supports parameter bounds, and is generally more forgiving of correlated nonlinear parameters than a basic single-start NLS fit. It still needs sensible bounds, informative data, and a reasonable starting point.

Turn the NLS fit into a reusable function

A reusable function should accept two vectors and return the same three named values every time:

SM + EF \(\rightarrow\) theta_d + theta_w + EF_max

fit_NLS <- function(SM, EF) {
  # Remove pairs with missing or non-finite values.
  keep <- is.finite(SM) & is.finite(EF)
  SM <- SM[keep]
  EF <- EF[keep]

  # Return this fixed-length vector when a fit is not possible.
  empty_result <- c(
    theta_d = NA_real_,
    theta_w = NA_real_,
    EF_max = NA_real_
  )

  # A nonlinear fit needs enough observations and SM variation.
  if (length(SM) < 10 || length(unique(SM)) < 4) {
    return(empty_result)
  }

  # Recalculate the same bounds for the data supplied to this fit.
  lower <- c(
    theta_d = 0.02,
    theta_w = unname(quantile(SM, 0.35)),
    EF_max = 0.20
  )
  upper <- c(
    theta_d = unname(quantile(SM, 0.30)),
    theta_w = unname(quantile(SM, 0.98)),
    EF_max = 1.00
  )

  if (any(!is.finite(c(lower, upper))) || any(lower >= upper)) {
    return(empty_result)
  }

  # Start at the midpoint of each allowed parameter range.
  start <- (lower + upper) / 2
  model_data <- data.frame(SM = SM, EF = EF)

  fit <- minpack.lm::nlsLM(
    EF ~ piecewise_EF(SM, theta_d, theta_w, EF_max),
    data = model_data,
    start = as.list(start),
    lower = lower,
    upper = upper,
    control = minpack.lm::nls.lm.control(maxiter = 200)
  )

  parameters <- coef(fit)[c("theta_d", "theta_w", "EF_max")]
  setNames(as.numeric(parameters), names(empty_result))
}

Many optimization methods can search for parameters of the same physical equation. For example, Particle Swarm Optimization (PSO) maintains a population of candidate parameter sets, called particles, and moves them through the bounded search space. Unlike nlsLM(), which follows a local least-squares path from one starting point, PSO explores several candidates at once and is stochastic. That broader search can help with difficult objective surfaces, but it is usually slower and requires a random seed and tuning choices.

Optional replacement: use PSO instead of nlsLM()

PSO changes the optimization engine, not the piecewise physical model, parameter meanings, bounds, or data. First define the mean-squared-error objective and a PSO fitting function.

model_error <- function(parameters, SM, EF) {
  predicted <- piecewise_EF(
    SM,
    theta_d = parameters[1],
    theta_w = parameters[2],
    EF_max = parameters[3]
  )
  mean((EF - predicted)^2)
}

fit_PSO <- function(SM, EF) {
  keep <- is.finite(SM) & is.finite(EF)
  SM <- SM[keep]
  EF <- EF[keep]

  lower <- c(
    theta_d = 0.02,
    theta_w = unname(quantile(SM, 0.35)),
    EF_max = 0.20
  )
  upper <- c(
    theta_d = unname(quantile(SM, 0.30)),
    theta_w = unname(quantile(SM, 0.98)),
    EF_max = 1.00
  )

  fit <- pso::psoptim(
    par = (lower + upper) / 2,
    fn = model_error,
    SM = SM,
    EF = EF,
    lower = lower,
    upper = upper,
    control = list(s = 30, maxit = 60, trace = 0)
  )

  setNames(fit$par, c("theta_d", "theta_w", "EF_max"))
}

Then replace only this line:

parameters <- fit_NLS(SM, EF)

with:

set.seed(analysis_seed)
parameters <- fit_PSO(SM, EF)

Everything after the fitting call can continue to use the same three named parameters.

Compare with a Random Forest

A Random Forest learns the SM–EF relationship from many regression trees. It does not assume the three-regime equation and does not directly estimate \(\theta_d\), \(\theta_w\), or \(EF_{max}\). It is therefore a useful black-box prediction benchmark, but it is less physically interpretable.

Random Forest is flexible, not physically constrained

The Random Forest response may be step-like or locally non-monotonic. Interpret it only within the SM range represented in the training data. Unlike the piecewise model, it does not provide physically defined threshold parameters.

Prepare the raster calculation

terra::app() passes one long vector for each cell. The first half contains SM and the second half contains EF.

n_time <- nlyr(SM)
spatial_data <- c(SM, EF)

Use tryCatch() for the full map so one failed cell does not stop all other cells.

fit_NLS_spatial <- function(x) {
  # Separate the combined vector into its SM and EF halves.
  SM_cell <- x[seq_len(n_time)]
  EF_cell <- x[n_time + seq_len(n_time)]

  tryCatch(
    fit_NLS(SM_cell, EF_cell),
    error = function(e) c(
      theta_d = NA_real_,
      theta_w = NA_real_,
      EF_max = NA_real_
    )
  )
}
Do not let tryCatch hide the cause

tryCatch() is useful when hundreds of cells are fitted, but it can hide why a model failed. Always test selected cells without it before running the complete raster.

Create the parameter maps

nls_parameter_maps <- terra::app(spatial_data, fit_NLS_spatial)

What should we conclude?

  1. minpack.lm::nlsLM() estimates interpretable parameters for the piecewise physical model.
  2. The bounds and starting values are part of the optimization workflow and should be checked explicitly.
  3. PSO is an alternative search algorithm for the same physical model, not a different scientific equation.
  4. Random Forest is a flexible black-box comparison and does not return the physical thresholds.
  5. A function that returns a fixed-length vector can be reused for raster-cell calculations.
  6. tryCatch() keeps a large calculation moving, but selected fits should first be tested directly.
  7. terra::plot(..., fun = add_states) keeps the spatial plotting code and legends simple.
